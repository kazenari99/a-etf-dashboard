## 数据源

生产流程统一使用**同花顺金融API**，不使用OpenD、东方财富、BaoStock或Tushare。端点：`https://fuyao.aicubes.cn/api/fund/market/historical`，仅服务端发送 `X-api-key` 请求头。使用前复权OHLC、真实成交额，单次获取约370自然日，至少121根完整日线。请求串行且间隔0.4秒；动态限流和上游错误采用有界指数退避，认证错误立即终止。源故障仅回退同源缓存并明确标记，绝不混用其他复权批次。认证失败（业务码2001/2003或HTTP 401/403）立即终止整次运行，不回退缓存。有效样本低于观察池90%时不发布，避免在缩小的样本上重算百分位导致评分口径漂移。日期对齐以基准510300的最新交易日为锚点。

[同花顺官方接口文档](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/fund/fund-market.md)和[使用约束](https://github.com/HiThink-Tech/Financial-API#使用约束)：目前不设累计调用次数上限，但有动态限流；实际权限以账户与服务端为准。

## 与美股版一致的模型

- 20/60/120日收益在完整有效观察池内进行百分位排名，分别加权30%/40%/30%，乘100。
- `Close > EMA20 > SMA50 > SMA120` 加5分；60日跑赢基准加3分；距EMA20超过2.5ATR扣8分。分数可超过100，不是胜率。
- 基准从美股SPY替换为沪深300ETF（510300）。收益、均线、ATR14、过热阈值、Momentum/等待回踩/回踩观察/趋势破坏条件与美股版相同。
- 回踩区=EMA20±0.5ATR；突破参考=前20日最高价+0.1ATR；失效参考=min(EMA20,近10日最低价)−0.5ATR。
- 本地合成OHLCV测试通过原美股 `analysis/etf_momentum_scan.py` 生成固定对照数据，逐项验证评分、状态、均线、ATR和参考价格的数值一致性。
- 仅日期窗口完全对齐且至少121根的ETF参与打分。排名是固定观察池内排名，筛选不改变评分。跨境、商品、债券也在观察池，遵循美股版跨资产排名逻辑，非全市场板块指数。
- 20日平均成交额使用同花顺实际成交额，而不是close×volume近似，单位人民币元。这影响散点大小，不影响评分。

## 周度清单（主规则 v2）与纸面跟踪

页面顶部的周度清单由 `strategy.py` 计算，规则 `near-high-250-skip5-top5-weekly-v2` 于 2026-11-21 冻结：

- 每周最后一个交易日收盘后（按 `trading_calendar.py` 判断，节前最后一天也算），在权益类ETF（A股、港股、海外，不含债券、商品、可转债，20日均成交额≥2000万元；`universe.ADDED` 中的新成员从加入日起才参与）中，按“5个交易日前的收盘价相对当时250日最高收盘价的距离”排序，并列按60日收益，取前5只。
- **下一交易日开盘**等权调仓，单边成本按0.1%扣除。页面直接列出“卖出 / 买入 / 继续持有”。
- 纸面跟踪从 2026-11-20 的收盘信号开始（2026-11-23 开盘建仓）。每周清单在首次算出时写入 `track/ledger.json`（`ledger.py`），只追加、不修改，由发布工作流提交到 main；跟踪持仓以这份记录为准，收益每次用价格重算。之后改观察池、参数或代码，也不会改写已记录的周次。页面会标出调仓日开盘后才补记的周次（`recorded_after_trade`），以及按当前代码重算与记录不一致的周次。原规则 v1（不跳过最近5日）仍按价格重算，作对照。

为什么是 v2：v1（按当天收盘价排序）的回测 +20.8% 假设在信号当天收盘价成交。改成次日开盘成交后只有约 +10%，信号晚一天只有约 +5%；拆分收益发现几乎全部来自创新高后的第一个交易日，收盘后才下单的投资者拿不到。跳过最近5日后，2022-12 至 2026-11（次日开盘成交、单边0.1%）年化 +14.0%、最大回撤 −19.4%，同期沪深300ETF +2.1%、等权 +2.5%；信号再晚一天仍约 +12%。

需要注意：

- 参数稍变（跳过3/5/10/20日、前3/5/10名）时，结果在约 +2% 到 +20% 之间，优势存在但幅度不确定；保守预期约年化 +5%～+12%、回撤 −20%～−30%。
- 分年度：下跌年份（2023、2026）明显跑赢，大涨年份（2024 跑输沪深300约7个百分点，2025 跑输等权约12个百分点）落后，偏防守。
- 观察池是事后挑选的，三轮分析共试过约40种做法；年换手约39倍；跨境ETF价格含溢价变化。以纸面跟踪为准。
- 清单中两只以上属于同类暴露（`universe.CLUSTERS`）时页面显示集中度提示；规则本身不去重。
- 生产抓取窗口为 `radar.fetch_days()`（至少560个自然日，随跟踪延长），以覆盖250日高点、5日跳过和整段跟踪。

## 大盘概览

原 REGIME 区块改为“大盘概览”：在原有宽度条和双动量状态下方，列出上证50、沪深300、中证500、中证1000、创业板、科创50 六个宽基ETF的距250日高点（与周度清单同一口径）、相对50/120/250日均线的位置、多头/空头/震荡排列、20日和60日涨跌，并自动生成一句总结，与周度清单的平均距高点对照。数据来自观察池已有的ETF，不增加接口调用。

它只作背景：2022–2026 回测中，沪深300跌破200日线换国债的择时年化 −0.6%，按“偏防守”换国债 −2.7%，都跑输一直持有沪深300（+2.8%），所以页面明确标注不作为买卖信号。

## 模型 v1.2 与回测结论

`model.py` 把模型拆成逐日面板计算（所有指标只用当日及以前的数据），生产页面和回测共用同一份代码。`model.V1` 与美股版逐位一致（`tests/fixtures/us_model_parity.json`），作为回测基准；页面发布的是 `model.PROD`（`a-momentum-v1.2`）：

- v1.2（2026-11-21）：百分位只在权益类ETF（A股、港股、海外）中计算；债券、商品、可转债不再有综合评分，表格状态显示“绝对动量成立/不成立”（120日收益高于货币ETF同期收益且收盘在120日均线上方）。此前国债ETF会和股票一起排名，可能被标为“动量成立”。回测与 v1.1 基本一致（20日 IC +0.005，前10超额 +0.25%）。“每日变化”只比较有评分的ETF。

- 不再对距EMA20超过2.5倍ATR的ETF扣8分，标签“强势·等回踩”改名为“加速强势”。
- 强势状态加缓冲：进入强势后，直到60日收益转负或跌破50日均线才退出。只影响标签，不影响评分。

2026-11-21 用2021-11至2026-11的同花顺日线回测（60只权益ETF、20日均成交额≥2000万元）：

| 方案 | 20日 Rank IC | Q5−Q1 | 前10超额 | 每日新进强势 |
|---|---|---|---|---|
| v1（美股公式） | +0.003 | +0.19% | +0.21% | 0.94 |
| v1.1 | +0.005 | +0.23% | +0.25% | 0.44 |
| v1.2（当前） | +0.005 | +0.20% | +0.25% | 0.44 |
| v2 合成候选 | +0.001 | +0.07% | +0.06% | 0.44 |

- 评分对之后20日收益**没有统计显著的预测力**（t 值约为0）；页面把它作为当前相对强弱的描述，不作为买卖信号。
- 加速强势（多头排列且距EMA20 > 2.5 ATR）之后20日平均跑赢约1.8%，按距离分档单调递增，2023–2026年每年为正，但 t≈1.3 仍不显著。v1.1 因此只取消扣分，不额外加分。
- v2 的其他候选（跳过近5日、风险调整、仅权益排名、同类去重、3日平滑）都没有稳定改善，保留在 `backtest.py` 里作对照，不上线。
- 偏进攻阶段 IC 为 +0.05、偏防守阶段为 −0.05，方向符合动量在熊市失效的规律，但按年份拆开不稳定。页面只把双动量状态作为背景提示。
- 60只ETF日收益平均两两相关0.45，独立样本远少于60只，所有结论的置信度都有限。`universe.CLUSTERS` 按近一年相关性≥0.95更新，在详情里提示同类暴露。

```sh
python backtest.py --fetch     # 用批量接口拉5年日线（每次10只），写入 reports/backtest.md
python backtest.py             # 用 data_cache/backtest_klines.json 重新评估
python backtest.py --synthetic # 合成数据，只用来检查流程
```

也可以在 Actions 手动运行 **Momentum backtest**，报告会出现在运行摘要和 artifact 里。所有方案都在同一批样本上评估（权益类、121日对齐、20日均成交额≥2000万元）。报告包括20/5日 Rank IC（t 值按不重叠窗口计算）、五分位收益、前10超额与换手、分年度和分市场状态的结果、状态标签的区分度，以及高相关ETF对（用来核对 CLUSTERS）。只有20日 IC、Q5−Q1、前10超额同时改善，并且至少60%的年份 IC 更高，才判为“改善”。

## 本地运行

需要 Python 3.11 及以上（仓库根目录有 `.python-version`，pyenv 会自动选用）。numpy/pandas 的版本锁定不支持更早的 Python。


```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# 设置环境变量 HITHINK_API_KEY，或将key保存至 config/hithink_api_key.txt（已gitignore）
python radar.py
python -m http.server 8766 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8766/`。HTML内嵌全部样式、脚本和数据，可离线打开。数据JSON作为发布与归档结构保留，不在页面提供下载入口。

- `python radar.py --offline`：只使用同花顺缓存，明确标注离线；不联网。缓存 `data_cache/hithink_klines.json` 不在 git 中（gitignore），需要先联网运行一次生成。离线运行不写入纸面跟踪记录。
- `python radar.py --render`：重新计算并重绘已保存批次，保留原数据采集时间；不联网。
- `python -m unittest discover -s tests -v`：模型一致性、日期对齐、错误与限流测试。

## 每日自动更新与发布

GitHub Actions工作日北京时间19:00计划执行，实际调度可能延迟。手动运行也会抓取更新。推送main时优先用Actions缓存中的上一批数据 `--render` 重绘、不调用API；缓存缺失、观察池有变更或有效样本不足时自动改为联网抓取。仓库Secret名为`HITHINK_API_KEY`；密钥只在抓取步骤注入，不出现在网页、JSON、代码、日志或缓存中。不要在前端调用带key的API。

首页：[JADE PULSE](https://jade-a.pages.dev/)。Pages只上传根路径首页，不再发布旧的 `/reports/etf_dashboard.html` 路径。每次联网运行按时间归档；Actions研究归档保留90天。本地归档路径`archive/YYYY-MM-DD/HHMMSS/`。源不可用且无足够缓存时发布失败，保留线上上一版。

运行监控：

- 定时或手动运行失败时，工作流会创建或更新 Issue「[自动更新失败] ETF 看板每日发布」，下次成功后自动关闭。
- 页面打开时按内嵌的交易日历自行判断：北京时间21:00后仍没有当天数据，或落后一个以上交易日，顶部显示“数据可能已过期”。
- `trading_calendar.py` 缺少当年的休市安排，或12月起缺少下一年的，工作流会开 Issue 提醒，页面运行记录也会显示。2027年的休市日按国务院通知（国办发明电〔2026〕10号）推算，交易所12月公布休市通知后需核对，并把该年从 `PROVISIONAL` 中移除。
- 新的周度清单记录推送失败时（例如 main 开启了分支保护），工作流会开 Issue 提醒。

原脚本已移至 `legacy/etf_dashboard.py`，与旧缓存一起保留作历史参考和原53只名单，已不再作为生产任务入口。A股快照与原美股/OpenD项目互不覆盖。

## 阅读与每日对照

首页按市场概览、全观察池板块热力表、每日变化、ETF明细和图表排列。板块表不受明细筛选影响，点击板块可筛选下方ETF。手机明细保留名称、20日收益、评分和状态，点击行查看完整指标。自选与筛选偏好仅存储于当前浏览器；重置筛选不会清空自选。

每日变化对比上次已发布的较早交易日期，明确显示对照日期；同日重跑沿用原对照。模型、数据源、基准和有效样本池必须一致，且双方均无缓存，才显示排名变化及状态转换。并列分数共享名次。首次或没有可比数据时显示暂无，不重算历史价格或推算旧排名。比较的是当时发布的观察结果，不是同一复权批次的回测。

观察池覆盖、13只新增ETF的官方核对来源及分类调整见 [观察池说明](docs/UNIVERSE.md)。生产名单独立于旧版脚本，维护在 `universe.py`。商品、债券与股票分组展示，跨资产评分公式不变；扩容会改变百分位排名，跨观察池版本不展示排名升降。
